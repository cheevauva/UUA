# Универсальная сервиторная архитектура

## Теримины

- **Предметная область (домен)** - область реального мира, которую описывает и оптимизирует программное обеспечение;
- **Доменная логика** - это слой в программной архитектуре, отвечает за бизнес-правила и обработку данных, относящихся к предметной области;
- **Бизнесс-логика** - это набор правил, процессов и операций, которые отображают предметную область;
- **Юнит, бизнесс-юнит (Unit)** - одно бизнесс-правило (операция, процесс);
- **Сервитор (Servitor, Servant)** - это объект, который содержит только один бизнесс-юнит;
- **Посредник (Mediator)** - изолирует один домен (субдомен) от другого;
- **Сервис (Service)** - это объект, который содержит больше одного бизнесс-юнита;
- **Сервисный слой (Service Layer)** - это слой в доменной логике, который содержит работу с сервиторами или сервисами;
- **Универсальная сервиторная архитектура (УСА)** - архитектура (концепция) построения слоя доменной логики с использованием сервиторов;
- **DAO (Data Access Object, ДАО)** - Объект доступа к данным. Паттерн проектирования, который предназначен для изолиции логики доступа к данным от бизнесс-логики;

## Unit (UnitInterface)

- ДОЛЖЕН содержить только ОДИН публичный метод (например: serve, run, exec, execute), метод должен возвращать void, а также не принимать входные параметры
- ЗАПРЕЩЕНО использовать сеттеры и геттеры для установки данных в Unit и получения данных из Unit 
- ЗАПРЕЩЕНО использовать конструктор для установки данных в Unit
- РАЗРЕШЕНО использовать публичные свойства для установки данных в Unit и получения данных из Unit 

## Servitor (Servant, Сервитор)  @todo

- Servitor ДОЛЖЕН расширять класс Unit и ДОЛЖЕН реализовывать принципы и ограничения описанные для Unit;
- Servitor ДОЛЖЕН принципу S из SOLID и реализовавать не больше одного конкретного бизнесс правила;
- предназначен для описание бизнесс-логики;
- РАЗРЕШЕНО вызывать DAO внутри Servitor (например: для работы с данными из внешних хранилищ (БД, текстовые файлы, кеши и так далее));
- Servitor РАЗРЕШЕНО вызывать внутри Servitor;
- Mapper ЗАПРЕЩЕНО вызывать внутри Servitor;
- Servitor МОЖЕТ иметь наследников;
- ЗАПРЕЩЕНО возращать данные в ассоциативных массивах;
- РАЗРЕШЕНО возращать данные с помощью скалярных типов данных, DTO, VO, Entity;

## Mediador

- Mediador ДОЛЖЕН расширять класс Unit и Mediador ДОЛЖЕН реализовывать принципы и ограничения описанные для Unit;
- Mediador ДОЛЖЕН принципу S из SOLID и реализовавать не больше одного конкретного бизнесс правила;
- предназначен для изолирования и инкапсуляции домена;
- Mediador ЗАПРЕЩЕНО вызывать внутри Mediador;
- РАЗРЕШЕНО вызывать DAO, Servitor внутри Mediador, но вызываемый DAO, Servitor должен быть на текущем или вложенном уровне неймспейса;
- РАЗРЕШЕНО возращать данные с помощью скалярных типов данных, DTO, VO, Entity;
- DTO, VO, Entity переданные в Mediador ЗАПРЕЩЕНО передавать в DAO, Servitor, обязателен маппинг на DTO, VO, Entity для вызываемых DAO, Servitor;
- DTO, VO, Entity возвращаемые из Mediador ЗАПРЕЩЕНО отдавать напрямую из используемых DAO, Servitor, обязателен маппинг на DTO, VO, Entity для вызываемых DAO, Servitor;
