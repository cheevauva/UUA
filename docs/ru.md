# Универсальная юнит архитектура

## Теримины

- **Предметная область (домен)** - область реального мира, которую описывает и оптимизирует программное обеспечение;
- **Доменная логика** - это слой в программной архитектуре, отвечает за бизнес-правила и обработку данных, относящихся к предметной области;
- **Бизнесс-логика** - это набор правил, процессов и операций, которые отображают предметную область;
- **Юнит, бизнесс-юнит (Unit)** - одно бизнесс-правило (операция, процесс), концептуальная сущность;
- **Сервитор (Servitor, Servant)** - это объект, который содержит только один бизнесс-юнит;
- **Сервис (Service)** - это объект, который содержит больше одного бизнесс-юнита;
- **Сервисный слой (Service Layer)** - это слой в доменной логике, который содержит работу с сервиторами или сервисами;
- **Универсальная юнит архитектура (УЮА)** - архитектура (концепция) построения слоя доменной логики с использованием сервиторов;
- **DAO (Data Access Object, ДАО)** - Объект доступа к данным. Паттерн проектирования, который предназначен для изолиции логики доступа к данным от бизнесс-логики;

## Введение @todo

Тейки: 
- является эволюцией серисного подхода (бизнесс-логика в сервисах);
- заменяет сервисный слой, но может и сощуществовать одновременно с ним;

## Unit (UnitInterface)

- ДОЛЖЕН содержить только ОДИН публичный метод (например: serve, run, exec, execute), метод должен возвращать void, а также не принимать входные параметры
- ЗАПРЕЩЕНО использовать сеттеры и геттеры для установки данных в Unit и получения данных из Unit 
- ЗАПРЕЩЕНО использовать конструктор для установки данных и внедрения произвольных зависимостей в Unit
- ЗАПРЕЩЕНО объявлять класс финальным
- ЗАПРЕЩЕНО объявлять потомков этого класса финальными
- РАЗРЕШЕНО использовать конструктор для внедрения контейнера зависимостей (или контейнера динамического контекста) в Unit
- РАЗРЕШЕНО использовать публичные свойства для установки данных в Unit и получения данных из Unit
- ЗАПРЕЩЕНО, если такое поддерживается языком, не указывать защиту от записи на свойствах, в которых пишется результат выполнения Unit;

## Servant (Servitor, Сервитор) 

- Servitor ДОЛЖЕН расширять класс Unit и ДОЛЖЕН реализовывать принципы и ограничения описанные для Unit;
- Servitor ДОЛЖЕН принципу S из SOLID и реализовавать не больше одного конкретного бизнесс правила;
- предназначен для описание бизнесс-логики;
- РАЗРЕШЕНО вызывать DAO внутри Servitor (например: для работы с данными из внешних хранилищ (БД, текстовые файлы, кеши и так далее));
- Servitor РАЗРЕШЕНО вызывать внутри Servitor;
- Mapper ЗАПРЕЩЕНО вызывать внутри Servitor;
- Servitor МОЖЕТ иметь наследников;
- ЗАПРЕЩЕНО возращать данные в ассоциативных массивах;
- РАЗРЕШЕНО возращать данные с помощью скалярных типов данных, DTO, VO, Entity;

## DAO

- DAO ДОЛЖЕН расширять класс Unit и DAO ДОЛЖЕН реализовывать принципы и ограничения описанные для Unit;
- DAO ДОЛЖЕН принципу S из SOLID и выполнять не больше одной конкретной операции с данными
- предназначен для доступа к данным и описанием локиги доступа к данным;
- DAO МОЖЕТ иметь наследников;
- ЗАПРЕЩЕНО вызывать Servitor внутри DAO;
- РАЗРЕШЕНО вызывать Mapper внутри DAO;
- ЗАПРЕЩЕНО вызывать DAO внутри DAO;
- ЗАПРЕЩЕНО вовзращать объект Mapper как результат работы DAO;

## Mapper

- ДОЛЖЕН расширять класс Unit и ДОЛЖЕН реализовывать принципы и ограничения описанные для Unit;
- Unit ДОЛЖЕН принципу S из SOLID и выполнять не больше одного типа конвератации данных
- предназначен для конвертации данных из одного формата в другой (например, конвертация строки выбранной из БД в Entity)
- ЗАПРЕЩЕНО вызывать DAO внутри Mapper;
- ЗАПРЕЩЕНО вызывать Servitor внутри Mapper;
- ЗАПРЕЩЕНО вызывать View внутри Mapper;
